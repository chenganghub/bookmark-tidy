# 模块接口（并行开发的契约）

数据类型全在 `src/core/types.ts`，这里写每个模块导出什么、行为怎么定。**签名照抄，不要改名**；要改类型或签名，先在交付说明里提出来，由主会话改。

通用约定：

- `src/core/*` 是纯 TS：不碰 `browser` / `chrome` 全局，浏览器能力通过参数传入（`BookmarksApi`、`KV`、`fetch`）。只用可擦除语法（不用 enum、namespace、参数属性）。模块之间 import 不带扩展名：`import { cleanTitle } from './rules'`。
- 只在信任边界校验：AI 输出、网页 HTML、导入的备份 JSON。类型保证了的不做运行时判断。
- 代码风格：2 空格、无分号、单引号；注释用中文，短，写「为什么」。
- 测试放 `tests/*.test.ts`，vitest，node 环境：`npx vitest run tests/xxx.test.ts`。

## plan.ts（子 agent D）

```ts
export const INBOX_NAME = '待整理'
export const CLEANUP_NAME = '待清理'
export const HOLDING_NAME = '整理前的空文件夹'
```

1. 参与整理的书签：在 barRootId、otherRootId 两个根下；不含锁定文件夹的子孙；`keepLooseBarItems` 时不含书签栏上直接放的；不含已经在「待清理」「整理前的空文件夹」里的（「待整理」里的照常参与）。
2. 目标：taxonomy → PlanFolder（key 用路径，如 '前端基础' / '前端基础/JS 技巧'）；classify 的 path 找到对应 key；置信度 < 0.6 → 'inbox'（low-confidence）；path 为空或不在树上 → 'inbox'（not-in-tree）；没有分类结果 → 'inbox'（ai-failed）。
3. 失效：`pageInfos[url].status === 'dead'` → 'cleanup'（dead）。只认 dead。
4. 重复：`normalizeUrl` 相同的一组，保留一条（dateLastUsed 最大 → dateAdded 最早 → id 最小），其余 → 'cleanup'（duplicate）。
5. 标题：`ruleTitle = cleanTitle(title)`（不同才有）；`aiTitle = meta[id].title`（不同才有）；`useRuleTitle = options.ruleTitles`；`useAiTitle = false`。
6. `oldFolderIds`：参与整理的书签所在的旧文件夹链（`folderIds`，不含锁定的）去重。
7. 规整：子目录 < 3 条 → 条目上提到父目录、删掉子目录；没有子目录的顶层目录 < 3 条 → 条目进 inbox、删掉；末级 > 40 条 → issue 警告。
8. `options.emoji` 为真时 PlanFolder.emoji 取 taxonomy 的 emoji。`treeFingerprint` 用 snapshot.ts 算。

顺序：预检 → 快照（`store.saveSnapshot` 等写完）→ `onSnapshot` → 日志 running（`saveLog`）→ 建目录（顶层目录按方案顺序插到 barRoot 的 index 0..n-1，子目录在父目录里按顺序；「待整理」「待清理」有条目才建，放 otherRoot 末尾，已有同名的复用）→ 移动（每步前 `get(id)` 核对 parentId / title / url 仍等于 base，不等就跳过记 changed-during-apply；同一目标按原来的先后顺序追加）→ 改标题（`finalTitle`）→ 旧目录：`oldFolderIds` 里父是根、此刻还在、整棵子树没有书签的，整个移进「其他书签/整理前的空文件夹」（不删，子目录跟着走）→ 读回整棵树逐条比对，差异进 `report.mismatches` → 日志 done。每做完一步 `done + 1` 并 `saveLog`，新建目录的 id 记进 `createdFolders`。出错：日志 failed、记 `error`，返回日志不抛。

```ts
export async function undoApply(api: BookmarksApi, log: ApplyLog, snapshot: Snapshot, store: ApplyStore, opts?: {
  onProgress?: (done: number, total: number) => void; now?: () => number

export async function alignToSnapshot(api: BookmarksApi, snapshot: Snapshot, opts?: {
  idMap?: Record<string, string>
  onIdMapped?: (snapshotId: string, newId: string) => void | Promise<void>
  removableFolderIds?: string[]     // 方案新建的目录：现在空了就删；不空就留，记 keptFolders
  onProgress?: (done: number, total: number) => void
}): Promise<UndoReport>
```

对齐算法：快照文件夹从浅到深处理；每个文件夹按快照 index 升序处理它的快照子节点 c：实际 id = `idMap[c.id] ?? c.id`；不存在 → `create`（在实际父文件夹的 c.index 处）并记 idMap；存在但父或位置不对 → `move(id, { parentId, index: c.index })`；标题 / 网址不同 → `update`。跳过根和永久文件夹本身（不能移动）、`unmodifiable`。快照里没有、却在快照文件夹里的节点（应用后新建的）会被挤到后面，记 keptExtras。（Chrome 同父移动时 index 大于旧位置会先减 1；按升序逐个放到位置 i 时，旧位置一定 ≥ i，直接给 i 就对。）

```ts
export function pendingCount(flat: FlatTree): number                        // 待整理 + 整理前的空文件夹 + 待清理里的书签数（弹窗「待处理 M」）
export function folderChoices(flat: FlatTree, lockedIds: Set<string>): FolderChoice[]   // 书签栏下前两层、不含锁定和 managed，path「父 / 子」
export function buildTriage(input: { flat; pages; lockedIds; records; plan? }): Triage  // unsure / cleanup（带原因）/ empty（按最上层分组，ids 深的在前）
export const batchRemovable: (cleanup: TriageEntry[]) => TriageEntry[]     // 原因还成立的（不是 other）
```

原因按顺序判：dead → 待清理以外有同一 `normalizeUrl` 的 → duplicate（写那一条的路径）→ unreachable → other。AI 猜的目录：自动整理记录（状态 inbox 的 `guess.folderId`）优先，再看方案（目标是待整理的条目的 `guess`，用 `reusedFolders` 换成文件夹 id）；都要在 `folderChoices` 里才预选。

`manual.ts`（只依赖 `BookmarksApi`）：`moveBookmarks`、`removeBookmarks`（记祖先链）、`removeFolders`（ids 深的在前，有东西的跳过）、`revertChange`、`ensureFolder`（同父同名、没锁定的直接用）。位置一律记那一步执行前那一刻的，撤销倒序；撤销边做边写 `change.rebuilt`（旧 id → 新 id），书签接口出错的那条算跳过、`onRebuilt` 出错直接抛出，再调一次从断点接着做。

`Workflow` 新方法（都在 `lock.run('manual')` 里）：`triage()`、`moveBookmarks(ids, target)`（移动的记进 `handPlaced`，change 里记这次新记的 `placed` 和移动前的自动整理记录 `records`）、`removeBookmarks(ids, onBackup?)`（给了 `onBackup` 先交出整棵树的快照 JSON，它抛错就不删；不存进快照库）、`removeFolders(ids)`（按 flat 的 depth 排深的在前）、`revertChange(change)`（重建的书签记进 `autoOwn`、复制旧 id 的 meta；移回去的从 `handPlaced` 移出、记录写回；新建的文件夹不删）。

`store.ts`：`getHandPlaced` / `addHandPlaced` / `removeHandPlaced`（键 `handPlaced`，先进先出 2000）；`Settings.badge`（默认 true）。`auto.ts` 的 `unfiledBookmarks` 多一个必填输入 `placed`；待整理里的不算、没有 7 天重算。
