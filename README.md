# 书签整理

Chrome 书签整理扩展（Manifest V3）。给每条书签写一句「这是什么」，用 AI 重新设计目录并逐条归类，再配一个能搜索的管理页。整理过一次之后，新收藏的网页自动放进对应的目录；工具栏弹窗和地址栏都能搜书签。整理先预览、应用前自动备份，能撤销；自动放的每一条都能撤销。AI 拿不准的、失效和重复的、腾空的旧文件夹，在管理页「待处理」里一条条放好或删掉。整理和自动放都不删书签，只有你点了「删除」才删，删了能撤销。

## 安装

1. 装依赖并构建（本机用 Node 24.9；统计工具直接导入 `.ts` 文件，要 Node 自带类型擦除的版本）：

   ```powershell
   npm install
   npm run build
   ```

2. Chrome 打开 `chrome://extensions`，打开右上角的「开发者模式」，点「加载已解压的扩展程序」，选 `.output/chrome-mv3`。
3. 点工具栏上的蓝色书签图标打开弹窗；弹窗右下角的「管理页」打开管理页。
4. 管理页右上角的齿轮是设置：填 DeepSeek 的 API key，点「测试连接」。

改了代码后重新 `npm run build`，再到 `chrome://extensions` 点扩展卡片上的刷新按钮。

## 怎么用

### 管理页

- **浏览**：左栏点文件夹筛选；按 `/` 或 `Ctrl+K` 搜索，标题、说明、标签、网址都能搜到；顶栏切换卡片和列表；标题行右侧按冷门、重复、要登录、失效筛选。点卡片直接打开网址。悬停时右上角出现三个按钮：移动（放到别的文件夹，或新建一个）、删除（结果条能撤销）、编辑说明和标签（手改的不会被 AI 覆盖）。
- **待处理**：顶栏的「待处理」，后面的数是要你拿主意的条数。分三类，每类一行说明：
  - 拿不准放哪：「待整理」和「整理前的空文件夹」里的书签。「放到」选一个文件夹就移过去；AI 当时猜过的目录预选好，点「放进去」；最后一项「新建文件夹…」（填名称，选放在书签栏还是某个顶层文件夹下）。也能删。
  - 建议删除：「待清理」里的，每条写原因：失效（打开是 404、410）、重复（写出另一条在哪）、连不上、原因已经不在了。能逐条删、放回去；「删除这 N 条」只删原因还成立的，先确认、下载整棵树的备份再删。
  - 空文件夹：整棵里没有书签的文件夹，按组勾选，「删除 N 个空文件夹」。
  - 每一步的结果条上都能撤销；三类都空了显示「都处理完了」。原来的体检（只用规则、不联网：重复、空文件夹、同名嵌套、可清理的标题、冷门等，点一张卡片列出对应的书签）收在底部「全部检查项」里。
- **整理**：顶栏的「整理」，按四步：
  1. 抓取网页信息（能跳过，抓了 AI 分得更准）。第一次点时 Chrome 会请求访问网站的权限。开抓前先列出抓多少、跳过多少，还能按文件夹、按域名取消勾选；内网、本机、带凭证参数、像操作链接（退出登录、退订、删除之类）的不抓；请求不带 Cookie。结果缓存 7 天。
  2. 生成方案：先给还没有说明的书签写一句，再设计新目录、逐条归类。
  3. 检查方案：「待整理」「待清理」两组排在最前、默认展开。可以改目录名、合并、移除目录（条目回「待整理」）、改单条的去向、取消单条（应用后算你定了不动，一键整理不再挪它）、选要不要改标题。
  4. 点底部的「应用」。应用后，结果条上的「撤销」能撤销。

### 收藏即整理

前提：在管理页「整理」里应用过一次，并且最近一次应用是「完成」（撤销了或没做完都不算）；给了访问网站的权限。弹窗里缺哪样就显示哪样（「还没整理过」「整理已撤销」「上次整理没做完」「没填 API key」「没有网页权限」），旁边是去处理的按钮。

1. 按 `Ctrl+D` 或点地址栏的星标收藏。扩展等 8 秒，留时间给你在 Chrome 的收藏气泡里自己挑文件夹。
2. 8 秒后发一次 AI 请求：写说明、标签、类型，规则能清理的标题改成清理后的，挑一个现有目录。把握不低于 0.5 的放进那个目录，低于 0.5 的放进「其他书签/待整理」。除了「待整理」（没有时建一个，一期就用这个名字），不新建目录。
3. 挪了位置的弹系统通知（你自己挑好文件夹的、本来就在对的目录的不打扰）：标题写放进了哪个目录，正文是说明；这个网页以前收藏过的，写出旧的那条在哪个文件夹。按钮「撤销」把它移回原来的文件夹和位置、标题改回去；「改位置」：放进目录的打开 Chrome 书签管理器里它所在的文件夹，进了待整理的打开管理页的「待处理」。弹窗的「最近收藏」里也能逐条撤销。

不处理的：

- 8 秒内（或 AI 返回前）你自己挪过的不移动，改过标题的不改标题。每条最多自动移动一次，之后你再挪走的不挪回去。
- 网址不在任何打开的标签页里的新书签（手机同步过来的、导入的、别的程序建的），以及导入书签期间建的。
- 收藏进锁定文件夹（含子文件夹）的：不发请求、不动。
- 等待期里你在管理页给它定了位置的：不再抓网页、问 AI。
- 8 秒内同一网页收藏两次的，只处理后一条。
- 一期的应用、从备份恢复正在进行时收藏的，等它做完再处理；撤销进行中收藏的，撤销完就不处理（撤销之后自动整理停着）。等了 10 分钟还没做完的（比如应用到一半关了页面）不再等，应用完成后算进一键整理。撤销、恢复重建出来的书签不处理。

自动整理默认使用 0.5 作为把握阈值。模型把握不等于分类正确率，可用 `tools/e2e/calibrate.mjs` 在自己的书签副本上校准。要改阈值就改 `src/core/store.ts` 的 `autoThreshold`；设置只存改过的项，改了对已经装好的也生效。

### 一键整理

弹窗里的「放好 N 条」。N 是还没放好的新收藏，工具栏图标上的灰色角标也是这个数（设置里能关掉角标）：

- 算进来：「其他书签」和「移动设备书签」根下直接放着的；最近一次应用之后新加、还没有说明的。
- 不算：「待整理」里的（在管理页「待处理」里处理）；锁定的；「待清理」「整理前的空文件夹」里的；书签栏上散放的（跟整理页的「散放不动」）；你定过位置的（待处理里放的、卡片上移动的、预览里没勾的、自动整理前你已经挪过的、一期方案里没勾的）；你撤销过或自己挪走过的；不是网页的（`chrome://`、`javascript:` 之类）。

点一次以后，AI 给了结果的都不再算（放进目录的、进了待整理的）；AI 请求失败的还算，结果里写几条没放成、原因是什么，下次再点会再试。N 为 0 时写「新收藏都放好了」。

N ≤ 10 时点了直接放，结果写放好几条、几条拿不准在待整理里（旁边「去处理」打开待处理），带「撤销这次」。N > 10 时先列出每条的去向，取消勾选的不动（算你定了不动），点「放好 N 条」才放。阈值和建目录的规则都和收藏即整理一样。

弹窗里还有一行「待处理 M」：要你拿主意的书签数（拿不准放哪 + 建议删除），点了打开管理页的待处理。

### 搜索

- 弹窗顶上的搜索框：边输边出结果，点一条打开，回车打开第一条。
- 地址栏：输入 `s`、空格、关键词。按标题、说明、标签、网址、目录名匹配，多个词都要命中，最多 6 条建议；选中一条打开它，直接回车打开管理页并带上这个搜索词。

自动放了几条、进待整理几条、撤销几条、7 天内又被挪走几条、地址栏用了几次，这些计数只存在本机（校准阈值时用），弹窗里不显示，也不发出去。

## 怎么关掉

管理页设置里：

- 「收藏时自动整理」：关掉后新收藏不再自动处理。弹窗里的一键整理和搜索照常能用。
- 「通知」：关掉后照样自动放，只是不弹通知（「最近收藏」里还能撤销）。
- 「工具栏角标」：关掉后图标上不显示数字，弹窗里的「放好 N 条」照常。
- 「发正文的网站」：清空后任何请求都不带正文片段。
- 「不读正文的网站」：加进去的网站不读正文、不存正文；请求里关于这个网页只有标题和域名，不发路径、简介和正文片段（候选目录照样附上，见下面「发给 DeepSeek 的数据」）。

整个扩展不想要了：在 `chrome://extensions` 里移除。书签留在原处，扩展自己存的数据随之删掉。

## 整理时的默认规则

- 锁定的文件夹（第一次打开时默认锁「受保护资料」，在整理页「锁定」里改）：不发给 AI、不抓网页、不移动、不改标题。
- 书签栏上直接放的书签不动（整理页的「散放不动」）。
- 书签栏顶层最多 8 个目录，最多两层；目录名默认不带 emoji。
- 标题：规则能确定的噪音（消息数前缀、站名后缀）默认清理；AI 建议的标题，勾了才写。
- 失效（404、410）和重复的，移进「其他书签/待清理」；AI 拿不准放哪的，进「其他书签/待整理」；整理后变空的旧文件夹，移进「其他书签/整理前的空文件夹」。这三处在管理页「待处理」里处理。
- 整理、收藏即整理、一键整理都不删除书签和文件夹；删除只在你在待处理或卡片上点了「删除」以后发生。
- 生成方案后你又在 Chrome 里改过的书签，应用时跳过，结果条的「详情」里列出来。

## 权限

| 权限 | 用来做什么 |
| --- | --- |
| `bookmarks` | 读写书签 |
| `storage` | 设置、说明、网页信息、快照、自动整理的记录存在本机 |
| `unlimitedStorage` | 收藏时读到的正文也存在本机，多了会超过默认的 10 MB 上限 |
| `favicon` | 显示网站图标 |
| `scripting` | 收藏时在那个标签页里运行抽正文的脚本（[Defuddle](https://github.com/kepano/defuddle)），读标题、简介和正文 |
| `notifications` | 自动放好后的通知和「撤销」「改位置」按钮 |
| `alarms` | 收藏后等 8 秒再处理；后台在等待期间被 Chrome 停掉时，闹钟约 30 秒后把它叫醒接着处理 |
| `https://api.deepseek.com/*` | 调 DeepSeek |
| 全部网站（可选） | 抓网页信息、读当前页正文、不带 Cookie 重抓公开版本。第一次抓取时，或者在弹窗里点「授权」时申请 |

`scripting`、`notifications`、`alarms`、`unlimitedStorage` 和地址栏关键字 `s` 是二期加的，主机权限没变。

## 发给 DeepSeek 的数据

锁定文件夹里的书签一条都不发，锁定文件夹的名字也不发。

整理（管理页）发：

- 书签标题；
- 网址的域名和路径（去掉协议、`?` 后的参数和 `#` 后的部分）；
- 抓到的网页简介（截到 200 字）；
- 所在文件夹的路径；
- 第一步生成的说明、标签、类型（给后两步设计目录和归类用）。

收藏即整理和一键整理，每条一次请求，发：

- 标题（清理后）；
- 网址的域名和路径；私有站点只有域名；
- 网页简介（截到 200 字），只用不带 Cookie 抓到的，标签页里看到的（可能是登录后的）不用；私有站点不发。和一期抓取一样，像操作链接的（退订、验证、退出登录之类）、带凭证参数或长随机串的、体检页里按域名排除的网站，不去请求，也就没有简介；
- 候选目录：书签栏下、不在锁定文件夹里的前两层目录的路径，和上次方案里每个目录的定义；
- 正文片段（只有收藏即整理会带）：网站在「发正文的网站」里（默认 CSDN、博客园、掘金、知乎专栏、思否、简书、GitHub、MDN），并且不带 Cookie 重新抓到的公开网页里能找到这段正文时，带正文的前 1500 字；找不到（比如只有登录后才看得到）就不带。私有站点（见下）就算也在「发正文的网站」里，也不读、不带。一键整理在后台跑，读不了标签页，不带正文。

不发书签当前所在的文件夹。私有站点 = 设置里「不读正文的网站」（默认飞书、Lark、钉钉）、内网和本机地址、锁定文件夹里出现过的网站（按主域名）。私有站点的网页，请求里只有标题、域名和候选目录：不发路径、简介、正文片段，也不去请求它。

发之前，邮箱换成 `{邮箱}`，11 位手机号换成 `{手机号}`，24 位以上同时含字母和数字的随机串换成 `{随机串}`。

收藏时读到的正文存在本机（每条最多 3 万字，最多 1000 条；书签删掉后，下次后台启动时一起删），除上面的正文片段外不发出去；私有站点的不读也不存。

API key 只存在本机的 `chrome.storage.local`，只放在发给接口的请求头里，不写进日志、快照和备份文件。

模型默认 `deepseek-flash`、关思考模式；接口地址和模型在设置里能改（OpenAI 兼容的接口都行）。

费用取决于接口供应商、模型、书签数量和输入输出 token；带正文片段会增加输入量。运行前请确认所用接口的当前计费规则。

## 撤销和恢复

- 应用前：扩展里存一份整棵树的快照（保留最近 5 份），同时下载一个 `书签备份-YYYYMMDD-HHmm.json`。
- 撤销：按快照把整棵树对齐回去。应用后没有别的改动时，每个书签和文件夹的 id、位置、标题、网址都和应用前一模一样；应用后在别处删掉的，按快照重建（id 会变）；应用后新建的保留。方案新建、撤销后已经空了的目录会删掉。
- 应用或撤销做到一半关了页面、浏览器崩了：再打开管理页，顶部会提示「上次应用未完成」，可以继续，也可以撤销。
- 从备份文件恢复：设置 →「从备份恢复」，选下载的 JSON 文件，走和撤销同一套对齐逻辑。
- 开着 Chrome 同步时，应用和撤销都会同步到其他设备。
- 自动放的：通知或弹窗「最近收藏」里的「撤销」撤一条；一键整理结果里的「撤销这次」撤一批。只撤你还没动过的部分：已经又挪走的不挪回，标题改过的不改回。
- 待处理和卡片上的移动、删除：结果条上的「撤销」。移动的移回原来的文件夹和位置；删除的重建到原来的文件夹和位置（文件夹也没了就先重建文件夹），标题、网址不变，说明跟着搬过去，id 和添加时间会变（「冷门」、按添加时间排序跟着变）。撤销「放到」不删新建的文件夹，空了会出现在「空文件夹」里。只能撤销最近一次，关掉管理页就撤销不了了；批量删前下载的备份文件可以用「从备份恢复」（浏览器拦下了下载的话就没有这份备份）。
- 删了书签以后再撤销一期的整理，快照里的书签会被重建回来，包括你删掉的。
- 一期的应用、撤销、恢复、自动整理，和待处理、卡片上的移动、删除、撤销共用一把锁，不会同时改书签。撤销、恢复每重建一条书签就记下来，自动整理不碰这些。剩下一个小缺口：从备份恢复正好在「建好一条」和「记下来」之间（毫秒级）崩溃时，那一条会被当成新收藏；只有它的网址正好开在某个标签页里，才会被自动挪一次，通知里能撤销。撤销没有这个缺口：撤销进行中和撤销之后，最近一次应用都不是「完成」，自动整理本来就停着。

## 开发

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | WXT 开发模式：热更新，自己开一个装好扩展的临时 Chrome |
| `npm run build` | 正式构建到 `.output/chrome-mv3` |
| `npm test` | 单元测试（vitest；书签接口用内存假实现） |
| `npm run compile` | 类型检查（vue-tsc） |
| `npm run icons` | 重新生成 `public/icon/` 下的图标 |
| `npm run audit` | 只读统计本机 Chrome 书签的现状，不改任何文件；加 `-- --json` 出机器可读结果 |

演示模式：管理页地址加 `?demo=1`，用内存里的假书签和假 AI，不碰真实书签。再加 `&theme=dark` 看深色，`&view=triage` 或 `&view=organize` 直接进待处理或整理（演示数据一开始没有要处理的，应用一次方案以后才有）。弹窗是 `popup.html?demo=1&state=idle|preview|running|result|partial|gate|empty`。

Windows 上的一个坑：npm 11.6 装 `defuddle` 时，会把 rolldown、lightningcss 带 `peer` 标记的 win32-x64 二进制从锁文件和 `node_modules` 里删掉，重装也补不回来。`package.json` 的 `optionalDependencies` 里固定了 `@rolldown/binding-win32-x64-msvc` 和 `lightningcss-win32-x64-msvc`；升级 wxt 或 vite 时，把这两个改成锁文件里 rolldown、lightningcss 对应的版本。

### 验证

端到端脚本都在临时 Chrome 配置里跑，结束后删掉临时配置；真实书签文件只复制、不写。终端只打印数字，不打印书签标题和网址。证据默认写到 `%TEMP%\bt-e2e`。

- `node tools/e2e/ui-check.mjs`：演示模式下按 `docs/设计规范.md` 逐项量样式和位置，走一遍浏览、卡片上的移动和删除、待处理（放进去、新建文件夹、批量删和它的备份、删空文件夹、撤销、都处理完了）、全部检查项、抓取、整理、应用、撤销和弹窗的各个状态，每个状态截一张图（默认存到 `%TEMP%\bt-shots`）。
- 下面三个要先 `npm run build:e2e`。它的产物多给了全部网址权限（自动化里点不了授权弹窗），还多几个测试用的后台消息，只用于测试。
  - `node tools/e2e/real-run.mjs --bookmarks "<Chrome 配置目录>\Bookmarks"`：用真实书签的副本、真实网络、真实 DeepSeek（读环境变量 `DEEPSEEK_API_KEY`）跑体检、抓取、生成方案、应用、撤销，逐项对照一期验收标准。加 `--no-ai` 不调 DeepSeek。
  - `node tools/e2e/auto-run.mjs`：假 AI、把 `*.bt-test` 映射到本机的假网页，逐项测收藏即整理、一键整理、地址栏搜索、正文和隐私规则。不联网、不花钱。
  - `node tools/e2e/calibrate.mjs --bookmarks "<Chrome 配置目录>\Bookmarks"`：离线校准，算各把握分段和方案一致的比例、选阈值（见上文）。要 `DEEPSEEK_API_KEY`；先跑一遍一期的抓取、说明、方案、应用，再每条一次请求；耗时和费用取决于书签数量及接口。

## 目录

```
entrypoints/
  background.ts      收藏即整理的调度、一键整理、地址栏、通知、角标
  extract.ts         收藏时注入标签页的抽正文脚本（Defuddle）
  popup/             工具栏弹窗入口
  manager/           管理页入口
src/core/            纯逻辑（全部有单测）
  rules.ts           体检规则、标题清理、网址规范化（命令行统计工具也用它）
  tree.ts            读树、拍平
  fetcher.ts         抓网页：跳过规则、队列、<head> 解析、不带 Cookie 抓公开正文
  sanitize.ts        发给 AI 前的脱敏
  ai.ts prompts.ts pipeline.ts   DeepSeek 客户端、提示词、分批
  plan.ts            整理方案、校验、预览编辑
  snapshot.ts apply.ts           快照、应用、撤销
  sites.ts text.ts   哪些网站不读正文、哪些能发正文片段；正文摘录和核对
  auto.ts autofile.ts            自动整理的判定；收藏即整理和一键整理的流程
  search.ts          搜索打分（弹窗、地址栏）
  triage.ts manual.ts            待处理的三类清单；移动、删除、删空文件夹和它们的撤销
  locks.ts           改书签的锁（一期操作、自动整理、待处理共用）
  store.ts workflow.ts           存储、把以上串成界面用的接口
src/ui/              界面组件、状态、演示数据；popup/ 是弹窗（样式在 popup.css）
tools/               统计工具、图标生成、端到端脚本
docs/                设计规范、模块接口、管理页草图
```

需求、验收标准、方案和进度记录在 `.agent/ctx/`（独立的记录仓库，不进本仓库）。
